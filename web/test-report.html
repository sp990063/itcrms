🔍 Diagnosis — SSO Auth Session Drop on Client-Side Navigation

  • All 5 roles successfully authenticate (Supabase OAuth redirect succeeds → session established).
  • Problem: After login, clicking nav links causes a redirect back to /auth/login — session cookie is lost on subsequent navigation.
  • Root cause likely: Supabase cookie storage issue with localhost:3001 — cookies not persisting across client-side route transitions, or Next.js middleware stripping auth cookies on non-OAuth routes.
  • Evidence: /cr/new works for all roles (direct URL visit after login), but /cr/my, /cr/all, and all /admin/* pages fail with login redirect.
  • OCR verified: 6 screenshots show "Submit New Change Request" form (PASS ✅). 19 screenshots show SSO login page (FAIL ❌).
  • Impact: RBAC cannot be enforced — users see login screen on every protected page except /cr/new.
